# Knowledge build inputs

The [ingestion framework](../README.md) builds the Fabric knowledge model from a **data bundle**: a folder of curated tables and public downloads that its producers turn into dataset folders. [`tools/make_bundle.py`](../tools/make_bundle.py) assembles the bundle. Almost all of it is generated from the packs this repository already ships, one file is downloaded from its public publisher, and one comes from your own deployment once its library is published. `infra/scripts/deploy.sh knowledge` runs all of this for you; this guide explains what it does and how to run it by hand.

## What the bundle holds

| Bundle path | What it is | Where it comes from | Producers that read it |
|---|---|---|---|
| `processed/geospatial/basins-pack.json`, `processed/application/app-pack.json`, `processed/application/lowcarbon-pack.json` | The application packs | This repository (`app/src/data`), copied | All of them |
| `processed/geology/fabric-iq-kit/` | The curated knowledge-graph kit: one table per entity type and one per relationship type, covering basins, units, plays, wells, structures, charts, core images and hypotheses | Generated from the packs by the app's own graph code ([`tools/export-kits.ts`](../../tools/export-kits.ts)) | `kit`, `ga_basins` |
| `processed/geology/ontology/*.ttl` | The same graph as OWL/Turtle, used for display labels | Generated by `tools/export-kits.ts` | `kit` |
| `processed/wells/wells.json`, `velocity.json`, `lowcarbon-sites.json` | Values read from the public well reports, with their pages and confidence | Written from the packs | `app_pack`, `well_reports` |
| `processed/seismic/seismic-figures.json` | The interpreted seismic figures | Written from the packs | `app_pack` |
| `source/geospatial/world-stress-map-2025/WSM_Database_2025.csv` | World Stress Map Database Release 2025 | Downloaded from GFZ | `wsm` |
| A copy of the library's published manifest (optional) | The sources and documents your live library has published | Your own deployment | `sources` |
| `SOURCE_MANIFEST.csv` (optional) | A per-file provenance list | Written by you | `sources` |

Everything generated from the packs carries only sources whose reuse terms allow redistribution, because the packs do.

## 1. Download the World Stress Map

The World Stress Map Database Release 2025 is published by the GFZ Helmholtz Centre for Geosciences under the Creative Commons Attribution 4.0 International licence, and every use must cite it:

> Heidbach, O., Rajabi, M., Di Giacomo, D., Harris, J., Lammers, S., Morawietz, S., Pierdominici, S., Reiter, K., von Specht, S., Storchak, D., Ziegler, M. (2025): World Stress Map Database Release 2025. GFZ Data Services. https://doi.org/10.5880/WSM.2025.001

Open https://doi.org/10.5880/WSM.2025.001 in a browser, which leads to the release page at GFZ Data Services, and download `WSM_Database_2025.csv` from its files section. Save it as `build/downloads/WSM_Database_2025.csv` and set `GBX_WSM_CSV` to that path in `infra/config/environment.env`, as the [reference profile](../../infra/config/live-equivalent.example.env) does.

The build was tested with a file whose SHA-256 is `3b24aa5b33b251b6c52ee25bcafe3d23d036deb1c38e1caae51f63b808605d1b` (14,931,069 bytes), and `make_bundle.py` prints the checksum of yours. A different checksum means GFZ has revised the file. The producer still reads it, because it uses only the release's standard columns, but the stress counts below may then differ slightly. The producer keeps only the Australian records.

## 2. Build the bundle

`deploy.sh knowledge` does this, including `npm ci` in `app/` when the app's packages aren't installed yet. By hand, from the repository root:

```bash
(cd app && npm ci)
python3 -m venv ingestion-framework/.venv
ingestion-framework/.venv/bin/pip install -e 'ingestion-framework[delta]'
cd ingestion-framework
.venv/bin/python tools/make_bundle.py --out ../build/bundle --wsm ../build/downloads/WSM_Database_2025.csv
```

The kit needs Node and the app's packages, because it is drawn by the same code the app uses for its knowledge graph (`app/src/lib/kg.ts`). `--no-kit` leaves it out.

## 3. Add your library's manifest (after the library is published)

Once your live library has published its sources ([content and expert review](../../docs/DEPLOYMENT.md#content-and-expert-review)), the knowledge model can list the same sources and documents. `deploy.sh knowledge` fetches the manifest from your site for you whenever the site answers. By hand:

```bash
python3 infra/scripts/live_content.py manifest build/live-manifest.json
export GBX_LIVE_MANIFEST="$PWD/build/live-manifest.json"
```

`live_content.py` asks the site's own API with your Azure CLI sign-in, so it doesn't need access to the private storage account. Set `GBX_LIVE_MANIFEST` to an absolute path, as above. Without it, the `sources` producer still describes the curated datasets and leaves the library out. Rerun the knowledge phase whenever the library publishes new sources, so the two stay in step.

## 4. Add a per-file provenance list (optional)

To have each downloaded file appear in the knowledge model, add `build/bundle/SOURCE_MANIFEST.csv` with one row per file. Only `file_name` is required. The producer links a file to its source when `original_source`, `description` or `source_url` names the source's eCat number or publisher, and keeps every other column as a property of the file, so columns such as `publisher`, `license_or_terms` and `checksum_if_available` are worth filling in.

## 5. Build and check

```bash
.venv/bin/python -m producers --bundle ../build/bundle --out ../build/landing --strict
```

`--strict` stops on any missing input instead of skipping its producer. With steps 1 to 3 complete and a library of the same 77 published sources, the landing folders hold:

| | Entity types | Entities | Relationship types | Edges |
|---|---|---|---|---|
| Step 2 without the World Stress Map | 28 | 26,281 | 48 | 24,926 |
| Steps 1 and 2 | 29 | 28,492 | 50 | 25,947 |
| Steps 1 to 3 | 29 | 28,649 | 52 | 26,033 |

The one entity type still absent is `SourceFile`, which step 4 adds. Values from the three sources withheld until their reuse terms are confirmed ([data sources](../../docs/DATA_SOURCES.md#how-sources-are-governed)) are never part of the bundle, by design.
